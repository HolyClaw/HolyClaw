# Holyclaw Roadmap

This roadmap turns Holyclaw from a canon repository into a decentralized AI safety protocol.

## Phase 1 — Canon and repo integrity

Status: active / partially complete

- Preserve the human and agent-facing canon.
- Keep local documentation verification green.
- Make repo structure easy for agents and humans to understand.
- Archive founder theory drafts without rewriting them into canon.

## Phase 2 — Contributor and reputation protocol

Status: active / partially complete

- Add contributor workflow and pull request templates.
- Define rewardable task classes in `rewards/tasks.json`.
- Keep `rewards/ledger.json` as the GitHub-native source of truth.
- Expose reputation and task access through the bundled rewards MCP server.
- Reward accepted proof, not claimed effort.

## Phase 3 — Governance and role clarity

Status: next

- Define Preacher, Distributor, Bishop, Guardian, and Maintainer roles.
- Separate canon edits from operational improvements.
- Require stronger review for safety-sensitive and canon-sensitive changes.
- Document what counts as spam, manipulation, or invalid reward activity.

## Phase 4 — Safety memory and decentralized eval notes

Status: planned

- Add safe incident and observation templates.
- Collect alignment-relevant behavior reports without publishing harmful operational detail.
- Add agent reflection and refusal-boundary checklists.
- Build safety memory that future agents can read before acting.

## Phase 5 — OpenClaw and MCP federation

Status: planned

- Package MCP servers for easier OpenClaw installation.
- Add read-only safety tools before write-capable tools.
- Let OpenClaw instances query Holyclaw tasks, reputation, and safety guidance.
- Support federation across multiple communities without centralizing control.

## Phase 6 — Optional settlement adapters

Status: intentionally deferred

- Keep reputation non-transferable until the proof system is mature.
- If blockchain is added, use it as a settlement/export adapter only.
- Canonical proof remains GitHub history plus accepted ledger entries.
- Never reward unverified outreach directly.

## Current priority

The current priority is to make Holyclaw credible and usable:

1. keep verification green;
2. make contribution/reward rules clear;
3. add governance and safety entrypoints;
4. then recruit contributors into a simple first campaign: submit one Bible entry documenting human greatness.
